## Исправлено (минорное)

`GetFanRpm`/`GetFanPercent`/`GetTemperatures`: унифицированы броски при
коротких/неудачных ответах вместо тихих нулей. XML-патч батарей переписан на
XDocument с верификацией повторного импорта (форматирование schtasks больше не
ломает патч молча). `Disable()` различает «задачи нет» и «удаление не удалось»
через предварительный `IsEnabled()`. Max-fan на плате без 0x27 коалесцируется в
Manual(100). Keep-alive не работает на отсутствующем железе. У MessageBox
появился владелец. `ReassertFanMode` в чистом Auto больше не шлёт три WMI-вызова
каждые 75 с. Debounce слайдера останавливается при закрытии формы + guard
`IsDisposed`. Выход из StartMinimized-режима не зависит от `OnFormClosed`.
`base.OnFormClosing` вызывается в cancel-ветке. Кисти в отрисовке карты/плиток
под `using`. Шрифты кэшируются по DPI на процесс (аллокации на каждый paint
убраны). Restore позиции окна зажимается в видимую рабочую область. Скрытые
(неподдержанные) плитки не оставляют дыр — слоты занимают только видимые.
ToggleSwitch переключается только левой кнопкой. OSD показывается на мониторе
курсора, а не только на PrimaryScreen. Optimus не подсвечивает кнопку Discrete.
crash.log пишется аппендом с датой в `%LocalAppData%` (нет гонок, нет перезаписи,
работает при неитаемой папке exe). Убрана HWND-утечка `HotkeyWindow` при неудаче
`RegisterHotKey`. Удалено мёртвое поле `AppSettings.MaxFan`. CI: `-alpha`-теги
публикуются как prerelease, pdb не попадает в архив. Манифесты: добавлена
секция supportedOS.

## 1. Найденные дефекты (исправлены)

### 1.1. Гонка в OSD-уведомлениях — `OsdForm.ShowToast`
`_active?.Close()` закрывает старую форму асинхронно; её обработчик `FormClosed`
обнулял `_active` уже после того, как туда была записана новая форма. При быстрой
смене режимов (Fn+P дважды) второй тост терял ссылку, и на экране висели
перекрывающиеся уведомления.
**Исправлено:** обработчик сравнивает ссылку (`ReferenceEquals(_active, form)`) и
обнуляет указатель только для своей формы.

### 1.2. Модальное окно ошибки из фонового watchdog — `TrayContext.Pump`
Keep-alive каждые 75 с повторно применял профиль; при любой ошибке WMI (занятость,
таймаут) пользователю в лицо выскакивал `MessageBox` — в том числе поверх
полноэкранной игры.
**Исправлено:** silent-операции теперь не показывают модальных окон; ошибка
попадает в статусную строку окна (`ErrorRaised`), модальность осталась только у
явных действий пользователя.

### 1.3. Гонки параллельных fan-задач
Переключения Max Fan / Manual из разных источников (окно, трей, watchdog) уходили
в `Task.Run` без ограничений — параллельные WMI-записи могли перебивать друг друга.
**Исправлено:** fan-команды идут через коалесцирующую очередь «последний выигрывает»
(по аналогии с очередью профилей).

### 1.4. Обратная связь тумблеров окна
Программная установка `Checked` у переключателей настроек вызывала
`CheckedChanged`, который тут же перезаписывал настройку тем же значением или
дёргал тяжёлые операции (автозапуск). Ползунок вентилятора аналогично запускал
 debounce-применение при каждом обновлении состояния из прошивки.
**Исправлено:** флаги `_suppressSettingsEvents` / `_suppressSliderEvent`.

### 1.5. Ошибки первого прохода новой вёрстки (найдено визуальным тестированием)
`FlowLayoutPanel` + `Dock=Top` в карточках не растягивал контролы; ручное
создание хэндла лишало окно восстановления из свёрнутого состояния.
**Исправлено:** детерминированная ручная раскладка `LayoutContent()` с двумя
проходами (учёт полосы прокрутки); поиск окна второй копии — через
`Process.MainWindowHandle` с Win32-активацией (в v2 заменено на
именованный EventWaitHandle, см. выше).

## 3. Отмечено на будущее (не исправлялось сознательно)

> Обновление (та же ревизия, что и capability-слой): пункт про «любой HP»
> закрыт — добавлены `CapabilityProbe`, адаптивный UI, `--info`, переключатель
> графики Hybrid/Discrete (`0x52`, с подтверждением и предупреждением о
> перезагрузке), fallback термополитики на Legacy, словарь кодов вентиляторов.
> Ограничение осталось одно: неигровые линейки HP не поддерживаются намеренно
> (в их прошивке нет `hpqBIntM`).

1. **`SetMaxFan(false)` и `FanCount` игнорируют коды возврата** (`PowerController`).
   Комментарий в коде объясняет это особенностью Victus S-series — часть прошивок
   отвечает ошибкой на «безвредный» запрос. Оставлено как есть: изменение поведения
   требует теста на железе всех ревизий.
2. **`FanModeCodes.Parse` не используется** приложением (только тестами). Чтение
   режима идёт через флаги GPU (`0x21`), которые надёжнее на Modern-платах.
3. **Вторая копия приложения не разворачивает окно, если оно спрятано в трей**
   (`MainWindowHandle == 0`). Полное решение — именованный pipe между процессами;
   запланировано на следующую ревизию.
4. **Ручной процент вентиляторов применяется к обоим вентиляторам одинаково**
   (`SetFanPercent(p, p)`). Прошивка поддерживает независимые значения — UI с двумя
   ползунками можно добавить после тестов на железе.
5. **Подсветка клавиатуры (OMEN `Cmd.Keyboard 0x20009`) не реализована** — на Victus
   обычно нет RGB; на OMEN 16/17 можно добавить через `0x04/0x05` (по данным OmenMon).
6. **`Thread.Sleep(50)` в `SetGpuPower`** — блокирует пул потоков. Убирать нельзя
   (двойная посылка требуется прошивке), но можно заменить на `await Task.Delay`
   при асинхронизации Core.
7. **Путь `crash.log` рядом с exe** — при установке в Program Files запись упадёт
   (тихо). Лучше `%LocalAppData%`, как у settings.json.
8. **Тесты покрывают только Core** — UI-слой (очереди, коалесценция) тестируется
   вручную. Стоимость UI-тестов для WinForms высока, приоритет ниже.
