# Архитектура и протокол VictusControl

Документ описывает внутреннее устройство утилиты, структуру WMI-пакетов HP BIOS и логику работы с прошивкой без использования OMEN Gaming Hub.

---

## 1. Общая схема взаимодействия

Взаимодействие с прошивкой ноутбука строится через интерфейс ACPI WMI, предоставляемый драйвером `acpi.sys`:

```
[Пользователь / CLI / Трей / Fn+P]
       │
       ▼
[PowerController] (оркестрация профилей)
       │
       ▼
[HpWmiClient] (сессия CIM root\wmi, класс hpqBIntM)
       │
       ▼
[acpi.sys] -> ACPI методы hpqBIOSInt0 / hpqBIOSInt4 / hpqBIOSInt128 (PNP0C14)
       │
       ▼
[HP BIOS / EC прошивка]
       │
   ┌───┴───────────────────────────┐
   ▼                               ▼
[VRM GPU]                       [VRM CPU]
cTGP + Dynamic Boost (PPAB)     Лимиты мощности
```

Этот подход работает при включенной изоляции ядра Windows 11 (Memory Integrity / HVCI = 1), поскольку не требует загрузки сторонних неподписанных или уязвимых драйверов ядра (вроде WinRing0).

---

## 2. Формат пакета WMI (hpqBDataIn)

Все обращения к BIOS Gaming-модуля HP выполняются через класс `hpqBIntM` в пространстве имен `root\wmi`.

### 2.1. Заголовок пакета

Входные данные передаются экземпляром класса `hpqBDataIn`:

| Поле CIM | Тип | Значение | Описание |
|---|---|---|---|
| `Sign` | uint32 | `0x55434553` (`"SECU"`) | Сигнатура безопасности HP BIOS |
| `Command` | uint32 | `0x20008` (131080) | Идентификатор Gaming / Thermal модуля |
| `CommandType` | uint32 | `0x1A`, `0x21`, `0x22`, `0x28` | Код конкретной субкоманды |
| `Size` | uint32 | Размер буфера данных | 0, 4 или 128 байт |
| `hpqBData` | uint8[] | Массив байт | Полезная нагрузка |

Ответ возвращается через экземпляр `hpqBDataOut` с кодом `rwReturnCode` и массивом `Data`.

### 2.2. Коды завершения (rwReturnCode)

- `0`: Успешное выполнение.
- `3`: Команда не поддерживается данной ревизией BIOS или платой.
- `5`: Неверный размер входного буфера данных.
- `1, 4, 6, 46`: Внутренняя ошибка прошивки HP.
- `-1`: Ошибка на уровне WMI/CIM операционной системы.

## 3. Субкоманды BIOS

### 3.1. Установка режима обдува и профиля (CommandType = 0x1A)

Метод: `hpqBIOSInt0` (вызов без возврата полезных данных).  
Размер входного буфера: 4 байта.

Формат полезной нагрузки:
```
Байт 0: 0xFF (фиксированный маркер)
Байт 1: Код режима (FanMode)
Байт 2: 0x00
Байт 3: 0x00
```

Коды режима зависят от версии Thermal Policy материнской платы:
- Modern V1 (платы 2023+ года, например 8C9C):
  - Eco: `0x50` (80)
  - Balanced: `0x30` (48)
  - Performance: `0x31` (49)
- Legacy V0:
  - Eco: `0x03`
  - Balanced: `0x00`
  - Performance: `0x01`

### 3.2. Управление лимитами GPU (CommandType = 0x22)

Метод: `hpqBIOSInt0`.  
Размер входного буфера: 4 байта.

Формат полезной нагрузки:
```
Байт 0: cTGP (Configurable TGP): 0x00 (выключен) или 0x01 (включен)
Байт 1: PPAB (Dynamic Boost): 0x00 (выключен) или 0x01 (включен)
Байт 2: DState: 0x01 (рабочее состояние питания)
Байт 3: Target Temp: 0x00 (0x00 сохраняет заводской лимит прошивки)
```

Матрица состояний GPU для профилей:
- **Eco**: `[0x00, 0x00, 0x01, 0x00]` (cTGP выключен, Dynamic Boost выключен). Видеокарта ограничена базовым TGP без буста.
- **Balanced**: `[0x00, 0x01, 0x01, 0x00]` (cTGP выключен, Dynamic Boost включен). Стандартный баланс мощности и шума.
- **Performance**: `[0x01, 0x01, 0x01, 0x00]` (cTGP включен, Dynamic Boost включен). Полный TGP с максимальным бустом (до 140 Вт на RTX 4070).

> Важное наблюдение: контроллер питания на некоторых ревизиях прошивок игнорирует первое переключение cTGP, если оно происходит сразу за сменой FanMode. Поэтому вызов субкоманды `0x22` выполняется дважды с паузой 50 мс между посылками.

### 3.3. Чтение текущего состояния GPU (CommandType = 0x21)

Метод: `hpqBIOSInt4` (возврат 4 байт).  
Входной буфер: 4 пустых байта `[0x00, 0x00, 0x00, 0x00]`.

Возвращаемые байты соответствуют структуре записи:
- Байт 0: `cTGP`
- Байт 1: `PPAB`
- Байт 2: `DState`
- Байт 3: `PeakTemp`

Определение текущего активного профиля производится по комбинации флагов:
- `cTGP == 1` и `PPAB == 1` -> **Performance**
- `cTGP == 0` и `PPAB == 1` -> **Balanced**
- Все остальные комбинации -> **Eco**

### 3.4. Чтение системных данных платы (CommandType = 0x28)

Метод: `hpqBIOSInt128` (возврат 128 байт).  
Входной буфер: 0 байт.

Байт по смещению 3 содержит номер версии Thermal Policy:
- `0x01` -> Modern V1 (используются коды 0x50 / 0x30 / 0x31).
- Любое иное значение -> Fallback на Legacy V0.

## 4. Сторожевой таймер прошивки (EC Watchdog)

В контроллере Embedded Controller ноутбуков HP заложен защитный таймаут: если внешнее управляющее ПО не обращается к регистрам в течение примерно 120 секунд, прошивка может плавно сбросить пользовательские лимиты вентиляторов обратно к стандартным значениям.

Для предотвращения тихого сброса трей-приложение содержит легковесный фоновый таймер:
- Интервал срабатывания: 75 секунд.
- Действие: повторная отправка активного FanMode и состояния GPU без всплывающего OSD.
- Нагрузка: 2 быстрых WMI-пакета, менее 1 мс процессорного времени.
- Опция отключается через пункт меню «Поддерживать режим активным».

## 5. Обработка событий и горячие клавиши

### 5.1. Аппаратная кнопка Fn+P и кнопка OMEN

Клавиатурный контроллер при нажатии комбинации `Fn+P` или клавиши с ромбом OMEN генерирует системное событие WMI в пространстве `root\wmi` (класс `hpqBEvnt`).

VictusControl подписывается на этот класс через `ManagementEventWatcher`:
- Запрос: `SELECT * FROM hpqBEvnt`
- `EventData`: 8613
- `EventId == 27 (0x1B)`: аппаратное нажатие `Fn+P`.
- `EventId == 29 (0x1D)`: нажатие фирменной клавиши OMEN.

При поступлении события происходит циклический переход: `Eco -> Balanced -> Performance -> Eco`.

### 5.2. Резервный глобальный хоткей

Если в конкретной редакции Windows или сборке драйверов поток WMI-событий заблокирован, работает резервный механизм Windows API:
- `RegisterHotKey`: комбинация `Ctrl+Shift+P`.
- Вызов обрабатывается в невидимом окне сообщений трея.

### 5.3. OSD индикатор (On-Screen Display)

При любом переключении режима (хоткей, клик по меню, даблклик в трее) в верхней части экрана на 1.2 секунды появляется полупрозрачный оверлей с названием и цветовой полосой режима:
- Зеленый: Экономичный
- Синий: Сбалансированный
- Красный: Производительный

Окно создается с флагами `WS_EX_NOACTIVATE` и `WS_EX_TOOLWINDOW`, благодаря чему оно гарантированно не перехватывает фокус ввода и не сворачивает полноэкранные игры.

## 6. Механизм автозапуска без диалогов UAC

Поскольку работа с `root\wmi` `hpqBIntM` требует административных привилегий, обычный запуск через ветку реестра `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` привел бы к появлению окна контроля учетных записей (UAC) при каждом входе в систему.

VictusControl использует планировщик задач Windows (`schtasks.exe`):
1. Создается задача с параметрами `/SC ONLOGON /RL HIGHEST /F`.
2. Экспортируется сформированный XML задачи.
3. В XML заменяются флаги питания:
   ```xml
   <DisallowStartIfOnBatteries>false</DisallowStartIfOnBatteries>
   <StopIfGoingOnBatteries>false</StopIfGoingOnBatteries>
   ```
4. Задача повторно импортируется в планировщик.

Благодаря этому приложение запускается с повышенными привилегиями сразу после входа пользователя, даже если ноутбук в этот момент работает от аккумулятора.
