# Методика тестирования и верификация железа

Документ описывает процедуру проверки работы утилит VictusControl на целевом ноутбуке и набор автоматических тестов.

## 2. Ручная проверка функциональности

Тестирование выполняется из терминала PowerShell, запущенного от имени администратора.

### 2.1. Базовая проверка CLI

```powershell
# 1. Проверка определения версии термопрофиля платы
.\VictusControl.exe --system
# Ожидаемый вывод: ThermalPolicy: Modern

# 2. Чтение текущего состояния видеокарты
.\VictusControl.exe --gpu
# В режиме Performance вывод: cTGP=1 PPAB=1 DState=1 Temp=87

# 3. Переключение в экономичный режим
.\VictusControl.exe --set eco
# Вывод: Applied: Eco

# Проверка регистра после переключения
.\VictusControl.exe --gpu
# Ожидаемый вывод: cTGP=0 PPAB=0 DState=1 Temp=87

# 4. Переключение в сбалансированный режим
.\VictusControl.exe --set balanced
.\VictusControl.exe --gpu
# Ожидаемый вывод: cTGP=0 PPAB=1 DState=1 Temp=87

# 5. Возврат в режим максимальной производительности
.\VictusControl.exe --set perf
.\VictusControl.exe --gpu
# Ожидаемый вывод: cTGP=1 PPAB=1 DState=1 Temp=87
```

### 2.2. Проверка аппаратных лимитов мощности (HWiNFO64)

Для контроля реальных изменений TGP используется утилита HWiNFO64 (раздел датчиков `GPU Power`):

| Профиль | Поведение вентиляторов | Ожидаемый пик мощности GPU | Dynamic Boost |
|---|---|---|---|
| **Eco** | Тихие, минимальные обороты | 50-65 Вт | Отключен |
| **Balanced** | Средний уровень шума | 80-100 Вт | Включен |
| **Performance** | Максимальные рабочие обороты | 115-140 Вт | Включен (полный TGP) |

Проверка проводится под игровой или синтетической нагрузкой (например, FurMark или TimeSpy) в течение 5-10 минут. Мощность GPU в режиме Performance должна стабильно держаться на целевой отметке без просадок до базовых 60-80 Вт.

### 2.3. Проверка фонового трея и горячих клавиш

1. Запустить `VictusControlTray.exe`.
2. В системном трее Windows должна появиться иконка соответствующего цвета (зеленый для Eco, синий для Balanced, красный для Performance).
3. Нажать комбинацию `Fn+P` на клавиатуре ноутбука:
   - Должен появиться экранный оверлей (OSD) с новым режимом.
   - Цвет иконки в трее должен измениться.
4. Нажать резервную комбинацию `Ctrl+Shift+P`:
   - Режим должен переключиться на следующий в цикле.
5. Повторный запуск `VictusControlTray.exe` должен развернуть окно уже работающей копии без создания второго процесса (проверка глобального мьютекса и сигнала активации).
6. В диспетчере задач проверить потребление ресурсов процессом:
   - Память: около 60 МБ (self-contained .NET 9).
   - Процессор: 0% в режиме ожидания (опрос датчиков останавливается, когда окно скрыто).

### 2.4. Проверка автозапуска

1. В разделе Settings главного окна включить «Start with Windows».
2. Проверить регистрацию задачи в системе:
   ```powershell
   schtasks /Query /TN VictusControl /FO LIST /V
   ```
3. Убедиться, что в свойствах задачи флаг `Stop If Going On Batteries` установлен в значение `No`.
4. Перезагрузить ноутбук при работе от аккумулятора.
5. Убедиться, что иконка трея появилась без запроса контроля учетных записей (UAC).

## 3. Модульное тестирование (Unit Tests)

Проект `VictusControl.Core.Tests` содержит набор модульных тестов, не требующих физического оборудования HP:

- **Интерфейсный шов `IHpWmiClient`**: позволяет эмулировать любые ответы прошивки, тестировать логику валидации входных параметров, последовательность отправки субкоманд (0x1A -> 50мс пауза -> 0x22 x2) и реакцию на коды ошибок BIOS.
- **Тесты переходов состояний**: проверка цикла `Eco -> Balanced -> Performance -> Eco`.
- **Тесты валидации путей автозапуска**: проверка изоляции путей исполняемых файлов в `AutostartManager`.

Запуск тестов в среде разработки:
```bash
dotnet test VictusControl.sln -c Release
```
